# 구 메달 코드 12 후속 조사

상태: 조사 도구. 자동 복구 규칙은 정하지 않았다.

2026-09-26 운영 DB에서 구 메달 코드 8~11의 확실한 대응 관계를 가진
47,092건을 복구했다. 실행 직전 전체 백업과 변경 전 47,092건의 파일을
보관했고, 사후 감사에서 해당 복구 후보가 0건임을 확인했다. 이 작업은
PR #170·#171의 코드를 병합하거나 Flyway를 실행한 결과가 아니라,
검증한 복구 스크립트를 운영 서버에서 직접 실행한 결과다.

구 갱신 스크립트 0.1.0.5에서는 이미지 코드 `none`을 숫자 12로 보냈다.
하지만 구 덤프에서 12로 저장된 기록 중 실제 메달이 흑동그라미였다는
사용자 확인 사례가 있다. 따라서 `12 → 현행 13(메달 없음)` 또는
`12 → 현행 10(흑동그라미)`를 일괄 적용할 근거가 없다. 코드를
메달 의미로 추측해 덮어쓰지 않는다.

이 PR의 `migration/bin/audit-ambiguous-medals.sh`는 다음을 확인한다.

- 구 덤프의 코드 12와 현재 기록을 `migration_playdata_map`으로 연결한다.
- 유저·채보·점수·버전 상태를 확인한다.
- 2026-08-30 00:00 KST 이후 갱신한 유저와 덤프 이후 갱신한 유저를
  검토 대상에서 제외한다.
- 현재 메달이 이미 바뀌었으면 별도 상태로 분류한다.
- 같은 유저·채보의 구 `history`에서 마지막 메달과 점수를 참고자료로
  집계한다. 이력이 같아도 실제 메달의 증명으로 사용하지 않는다.

2026-09-26 읽기 전용 조사에서는 원본 코드 12가 10,458건, 연결된 기록은
10,457건이었다. 연결되지 않은 1건은 별도 확인이 필요하다. 8월 30일
이후 갱신으로 제외된 기록은 1,613건이며, 검토 대상은 8,844건이었다.
모두 점수가 0보다 컸다. 그중 3,557건에는 구 이력이 있었지만 가장 최근
이력의 메달도 전부 12였고, 5,287건에는 이력이 없었다. 따라서 이력만으로
흑동그라미와 메달 없음을 나눌 수 없다. 운영 갱신에 따라 이 건수는 변한다.

도구의 기본 출력은 상태별 건수만 포함한다. `--review-file`을 지정하면
팝토모 ID·채보 ID·곡 해시·점수 등이 담긴 목록을 저장소 밖의 권한 600
파일로 생성한다. 이 파일을 Git이나 PR에 올리지 않는다.

개별 보정은 원본 게임 화면이나 유저가 확인한 기록 등 채보별 근거가 있을
때만 고려한다. 그때도 갱신 여부를 다시 확인하고 변경 전 값을 보관한 뒤,
메달에 의존하는 잠재 팝클과 최고 클리어 레벨 캐시를 함께 갱신해야 한다.
이 PR은 기록을 수정하거나 자동 재분류하지 않는다.
